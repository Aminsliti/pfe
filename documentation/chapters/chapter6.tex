\chapter{Sprint 2: V-GRC Integration and Risk Synchronization}

\section{Introduction}

This chapter presents Sprint 2 of the V-BPM platform. The objective of this sprint is to connect the BPM environment with the external V-GRC repository so that risk information can circulate between both systems in a controlled and traceable way. This sprint builds on the BPMN editor, the process management module, and the procedure manual generator already implemented in previous sprints.

The integration target is twofold. First, V-BPM must be able to retrieve risks that already exist in the GRC repository so they can be reused when modeling or documenting processes. Second, when a new risk is created in V-BPM and does not yet exist in the external repository, the platform must be able to publish it to the GRC database and keep the relationship between the local process context and the remote risk record.

\section{Sprint 2 Implementation}

This section presents the implementation logic retained for Sprint 2 in relation to the platform that was developed in the previous sprints. The goal is to show how the existing BPM modules are extended so they can exchange risks with the V-GRC repository.

\subsection{Use Case Implementation -- Synchronize Risks from V-GRC}

On the V-BPM side, the synchronization entry point is naturally connected to the process modeling and process management modules. The BPMN editor already allows the user to associate risks with process elements, while process management already centralizes the generated procedure manual and the risk matrix. Sprint 2 extends these modules with a synchronization service capable of requesting the external risk catalog before the user decides whether to reuse an existing risk or define a new one.

In practice, when the user opens a risk-related action, the platform calls the integration service, which queries the V-GRC repository and returns the relevant risks in a normalized format. This synchronized list is then exposed inside V-BPM so the user can link an existing governance risk to a BPMN task, a subprocess, or a manual section.

\subsection{Use Case Implementation -- Publish New Risks to V-GRC}

The second implementation flow starts from the local creation of a risk inside V-BPM. This can happen while modeling a process, while enriching the procedure manual, or while documenting control points related to a process activity. Once the user saves the new risk, the synchronization layer checks whether an equivalent entry already exists in the external repository. If the risk is not found, it is inserted into the V-GRC database and a remote identifier is returned.

This mechanism ensures that the BPM platform remains operational even when the risk is first created locally, while also guaranteeing that the GRC repository is progressively enriched instead of remaining disconnected from operational process knowledge. It also improves traceability, since the same risk can later be reused in both environments.

\section{Conclusion}

Sprint 2 completes the BPM--GRC convergence targeted by the project. It introduces the integration logic required to reuse risks already maintained by the governance repository and to publish new BPM risks when they are created from operational process work. By connecting process modeling, procedure manuals, and external governance data, this sprint strengthens consistency between execution, documentation, and risk supervision.
